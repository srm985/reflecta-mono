# AGENTS.override.md

## Scope

This package contains the Reflecta React / TypeScript web UI.

## Architecture

- Entrypoint: `src/index.tsx` bootstraps `src/bootstrap.tsx`, which mounts `App`.
- `src/App.tsx` owns `BrowserRouter`, route wiring, the global loading overlay, `RootStylingComponent`, and auth-gated routes.
- Route constants live in `src/routes.ts`; keep UI route paths and API route slugs centralized there.
- Protected screens sit inside `components/enhancers/AuthenticatedRouteComponent`; common navigation/layout is in `components/enhancers/ContainerComponent`.
- Redux Toolkit store setup is in `src/store/index.ts`; feature slices live in `src/store/slices/*`.
- API calls should go through `src/utils/Client.ts`, which attaches the bearer token from `Authentication`, uses `BASE_URL_API`, serializes GET params, sends credentials, and converts Axios errors into `HTTPError`.
- Auth state is currently client-side local storage based: `Authentication` reads/writes `LOCAL_STORAGE_AUTHENTICATION_TOKEN_KEY`.
- Journal draft auto-save uses `Storage` and `LOCAL_STORAGE_AUTO_SAVE_KEY`.
- Views are directory-based under `src/views/*` with colocated `types.ts` files where needed.

## Working preferences

- Preserve existing UI patterns before introducing new ones.
- Infer routing, screen/page structure, hooks, forms, fetching, state management, and styling conventions from nearby code.
- Keep components small and presentational where practical.
- Avoid pushing API logic directly into UI components when it belongs in an existing client, hook, store, or service layer.
- Prefer shared/imported types over local parallel types.
- Prefer `type` aliases over `interface` for new TypeScript shapes. Use `interface` only when declaration merging, extending an existing interface, or an established local pattern makes it the clearer choice.
- If a component needs reusable types, prefer a colocated `types.ts` file when that is already the local pattern.
- Do not create inline function-signature types.

## UI constraints

- Keep federated component imports aligned with `reflecta-components` public exports.
- Import shared UI primitives through generated wrappers under `@components/remotes/*` when rendering remote components.
- The remote wrapper files under `src/components/remotes` are generated by the UI webpack build from `../reflecta-components/declarations/src/components`; avoid hand-editing them.
- Do not hard-code backend URLs, remote component URLs, or deployment hostnames when existing configuration or environment wiring should be used.
- Treat Module Federation integration as runtime-sensitive.
- UI webpack expects `FEDERATED_COMPONENTS_URL`, `WEBPACK_SERVER_PORT_UI`, `NODE_ENV`, and `BASE_URL_API`; `.env` also includes `GOOGLE_MAPS_API_KEY` and `LOCAL_STORAGE_AUTHENTICATION_TOKEN_KEY`.
- Avoid app-specific logic inside components that should stay presentational.
- Use backend contract types when UI behavior depends on backend data shapes and a source-of-truth type is available.
- API payload mapping is explicit: UI journal submissions use `title/body/location/occurredAt`, while backend route bodies expect `entryTitle/entryBody/entryLocation/entryOccurredAt`.
- Authentication relies on both the local token signature and backend cookie header payload. Be cautious changing login, logout, `Client`, or backend cookie behavior.

## Style preferences

- Prefer early returns.
- Avoid nested ternaries.
- Avoid spaghetti code and deep chains of functions that primarily call other single-use functions.
- Keep component and hook logic direct unless abstraction materially improves reuse, testability, or understanding.
- Do not destructure props or params in the function signature; destructure inside the function.
- Prefer descriptive variable names and avoid abbreviations.
- Preserve existing formatting and import ordering.
- Follow existing alias usage from webpack/tsconfig (`@views`, `@store`, `@utils`, `@routes`, `@components`, etc.) instead of long relative imports.
- Existing JSX often uses string literals in braces, FontAwesome icons, and shared component layout helpers; match nearby style unless the task is explicitly a redesign.

## Verification

Use best judgment, but for UI-local work prefer:
- relevant lint and typecheck,
- targeted tests when available,
- UI build validation when routing, bundling, or environment configuration changes,
- validating `reflecta-components` integration when federated imports or shared component props change,
- call out when browser validation is still recommended.

Useful commands:
- `npm run lint -w reflecta-ui`
- `npm run lint:js -w reflecta-ui`
- `npm run lint:scss -w reflecta-ui`
- `npm run build -w reflecta-ui`
